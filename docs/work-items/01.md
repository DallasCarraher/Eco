# Build a bounded, resumable native experiment runner for overnight batches

GitHub: [#1](https://github.com/DallasCarraher/Eco/issues/1)

## Objective
Implement scripts/run_experiments.py against docs/EXPERIMENTS.md and experiments/jak1-startup.json. This runner executes an already-built binary; it does not modify translations or call a model.

## Dependencies
None. First implementation priority.

## Likely files
New scripts/run_experiments.py and synthetic harness tests; experiments/jak1-startup.json; docs/EXPERIMENTS.md.

## Work
- [ ] Validate the manifest, resolve absolute paths, fingerprint inputs and detect actual backend availability.
- [ ] Expand scenario × variant × repetition, pairing repeats early; fresh process/card and unique artifact folder per case. Clear inherited PS2_* settings.
- [ ] Enforce wall-clock, output, free-disk and process-tree limits; lock shared resources and save atomic reports after each case.
- [ ] Implement hash-validated resume and first-divergence summary; classify runtime halts independently of exit codes.

## Acceptance
- [ ] Synthetic tests cover normal frame limit, zero-exit halt, missing summary, child timeout/cancellation, quota, unavailable GPU, locks, resume mismatch and paths with spaces.
- [ ] Run the synthetic toolchain fixture, then the documented three-case Jak pilot; report backend, repeatability and missing captures honestly.
- [ ] A full batch needs no network, model calls or user interaction after launch; remaining cases are recorded when budgets expire.

## Stop conditions
Stop after the pilot and report. Do not launch the full overnight matrix automatically, change runtime semantics, or expand budget to conceal a slow case.

## Agent handoff
Use a codex/<issue>-<topic> branch and dedicated checkout. Keep expensive loops in bounded deterministic programs; no model/API calls inside experiment runners. Return commit, exact commands, synthetic checks, result paths, first actionable finding and remaining limits. Do not commit ISO, BIOS, extracted assets, game-derived translations or captures. The local work-item file is docs/work-items/01.md. Issue numbers in dependencies will be linked in the work-item index.
