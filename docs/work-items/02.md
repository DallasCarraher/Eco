# Make native and browser startup input replays and captures comparable

GitHub: [#2](https://github.com/DallasCarraher/Eco/issues/2)

## Objective
Give native and browser probes the same guest-frame input script and capture checkpoints. Browser wall-clock polling must not determine when a button is pressed.

## Dependencies
#1 for shared result schema; implementation may be developed independently.

- [Roadmap](https://github.com/DallasCarraher/Eco/blob/main/docs/ROADMAP.md)

## Likely files
scripts/jak_browser_probe.cjs, host/web.cpp, web/shell.html, native input scheduling and shared scenario parser as needed.

## Work
- [ ] Reuse boot-idle and boot-start from the manifest, including explicit two-frame Start pulse.
- [ ] Schedule input at the emulated pad sampling boundary and verify capture timing. Preserve interactive defaults.
- [ ] Write browser results to caller-selected unique output directories; capture source/build/browser/backend identities and terminal reasons.
- [ ] Use fresh Chrome profiles and a local server with explicit lifecycle ownership; close only processes created by the run.

## Acceptance
- [ ] A synthetic input fixture proves matching native/WASM button states on the intended guest frames.
- [ ] Native and browser produce the same scenario/checkpoint IDs and distinguish observation limit, runtime halt and frame limit.
- [ ] Two repeated runs expose nondeterminism instead of treating missing or misaligned screenshots as comparable.

## Stop conditions
Stop if frame semantics differ; document the divergence before drawing graphics conclusions. Do not modify rendering or automatically classify gameplay as verified.

## Agent handoff
Use a codex/<issue>-<topic> branch and dedicated checkout. Keep expensive loops in bounded deterministic programs; no model/API calls inside experiment runners. Return commit, exact commands, synthetic checks, result paths, first actionable finding and remaining limits. Do not commit ISO, BIOS, extracted assets, game-derived translations or captures. The local work-item file is docs/work-items/02.md. Issue numbers in dependencies will be linked in the work-item index.
