# Measure browser loading, frame pacing and memory after correctness gates

GitHub: [#8](https://github.com/DallasCarraher/Eco/issues/8)

## Objective
Create reproducible cold/warm loading and steady-gameplay benchmarks on the named Mac mini/browser, then prioritize measured bottlenecks.

## Dependencies
#7. Do not begin optimization before the tested gameplay route is correct.

- [Roadmap](https://github.com/DallasCarraher/Eco/blob/main/docs/ROADMAP.md)

## Likely files
Browser measurement tooling, docs/PERFORMANCE.md and narrowly justified delivery/runtime changes.

## Work
- [ ] Record browser/hardware/build and fixed route; separate shader compilation/loading from steady gameplay.
- [ ] Measure raw/compressed payload sizes, cold/warm startup, frame-time percentiles and memory using available APIs; label unavailable measurements.
- [ ] Repeat runs and report variability; distinguish emulated frame throughput from displayed frame pacing.
- [ ] Propose numerical targets from baseline/device requirements, then optimize one measured bottleneck with correctness reruns.

## Acceptance
- [ ] One reproducible report contains definitions, repeats and honest API limitations.
- [ ] Proposed performance targets are explicit, not retroactively tuned to pass.
- [ ] Any optimization retains the gameplay and graphics acceptance results.

## Stop conditions
Do not publish game-derived WASM/assets, add hosting or declare broad browser support as part of benchmarking.

## Agent handoff
Use a codex/<issue>-<topic> branch and dedicated checkout. Keep expensive loops in bounded deterministic programs; no model/API calls inside experiment runners. Return commit, exact commands, synthetic checks, result paths, first actionable finding and remaining limits. Do not commit ISO, BIOS, extracted assets, game-derived translations or captures. The local work-item file is docs/work-items/08.md. Issue numbers in dependencies will be linked in the work-item index.
